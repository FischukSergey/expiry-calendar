# Duekeep — календарь обязательств

Функционал согласован 2026-08-21. Архитектура: [ARCHITECTURE.md](ARCHITECTURE.md).

**Duekeep** — личный и семейный/командный учёт всего, у чего есть срок: домены, подписки, аренда, договоры, страховки, лицензии, налоги, ТО автомобиля. Главный вопрос продукта: *что сгорит в ближайшие дни и сколько это стоит*.

---

## Стек (черновик)

| Слой | Решение | Комментарий |
|---|---|---|
| Backend | **Go 1.25** | зафиксировано |
| Запуск | `deploy/` + корневой `docker compose up` | local демо-пароли; prod — `.env` на VPS |
| Frontend | React + TypeScript + Vite | зафиксировано |
| БД | PostgreSQL | иерархия категорий, JSONB, фильтры |
| Реалтайм | SSE + Web Push | вкладка открыта — SSE; свёрнуто / PWA — пуш в ОС |
| Клиент | PWA | установка на домашний экран, офлайн-заглушка |
| Auth | JWT access + refresh | access 15 мин, refresh 14 дней с ротацией; готово к нескольким клиентам |

---

## Пользователи и роли

Регистрация и вход выдают **JWT access + refresh**. Данные в v1 общие; после v1 свои строки по пользователю ([Sprint 7](docs/sprint-7-plan.md)), без org.

| Роль | Права |
|---|---|
| **admin** | полный CRUD записей, категорий, бюджетов уведомлений; продление; импорт/экспорт; просмотр журнала |
| **viewer** | просмотр записей, календаря, дашборда; поиск и фильтры; экспорт CSV |

Демо-аккаунты в seed (пароли только для локального демо, в README):

- `admin@duekeep.local` — admin
- `viewer@duekeep.local` — viewer

Оба видят **общий** набор демо-данных (одна «семья / домашняя лаборатория»), без мультитенантности в первой версии.

## Основные сущности

### Запись (item)

Единица учёта со сроком действия.

| Поле | Описание |
|---|---|
| title | название |
| description | свободный текст |
| kind_id | тип из справочника `item_kinds` (не хардкод enum) |
| attrs | JSONB: поля, специфичные для типа (VIN, регистратор, номер полиса) |
| vendor | поставщик / регистратор / страховая |
| category_id | ссылка на категорию |
| tags | несколько текстовых меток |
| cost_amount | стоимость (может быть 0) |
| currency | ISO-код, в демо — `RUB` и `USD` |
| billing_period | `one_time`, `monthly`, `yearly` |
| started_at | дата начала / покупки |
| expires_at | дата обязательства |
| notify_before_days | персональный порог, по умолчанию `30`; `null` — не уведомлять ([Sprint 9](docs/sprint-9-plan.md)) |
| url | ссылка на кабинет / админку |
| account_hint | подсказка (логин, номер договора) **без паролей** |
| status | см. ниже |
| created_at / updated_at | служебные |

**Статусы** (часть вычисляется, часть задаётся вручную):

| Статус | Смысл |
|---|---|
| `active` | срок ещё далеко (дальше порога) |
| `expiring` | до `expires_at` осталось ≤ `notify_before_days` |
| `expired` | срок уже прошёл |
| `cancelled` | отменено вручную, в дашборд «сгорит» не попадает |
| `archived` | скрыто из основного списка, доступно фильтром |
| `paid` | оплачено вручную (в т.ч. заранее); в «сгорит» не попадает; тикер не затирает и не уведомляет ([Sprint 9](docs/sprint-9-plan.md)) |

Правило: `cancelled`, `archived` и `paid` не пересчитываются автоматически. Нет notification, если `notify_before_days: null` **или** статус `paid`.

### Тип записи (item_kind)

Справочник, не закрытый enum в коде. Seed: `domain`, `subscription`, `rent`, `contract`, `insurance`, `license`, `tax`, `vehicle`, `mobile`, `other`  
(Домен, Подписки, Аренда, Договор, Страховка, Лицензия, Налог, Авто, Мобильная связь, Прочее).

- новый slug на инсталляции — через seed / `EnsureKinds` ([Sprint 9](docs/sprint-9-plan.md): `mobile`); UI «добавить тип» нет;
- admin по API по-прежнему может `POST /kinds`, с формы записи это не открываем;
- у типа есть `attr_schema` — какие дополнительные поля показать в форме;
- специфика хранится в `items.attrs`, общие поля срока и денег — в колонках;
- удаление типа запрещено, пока на него ссылаются записи;
- фильтры и дашборд идут по `kind_id`, не по ключам JSONB.

### Категория

Иерархия (например: `IT → Домены`, `Дом → Техника`, `Авто`).

- CRUD категорий
- перенос записи в другую категорию
- глубина в первой версии — до 3 уровней
- удаление категории запрещено, пока есть записи или подкатегории

### История продлений (renewal)

Каждое продление фиксируется отдельно:

- дата операции
- кто продлил
- старый / новый `expires_at`
- старая / новая цена
- комментарий

Продление **не удаляет** старую запись, а сдвигает срок и пишет историю.

### Уведомление (in-app)

- создаётся, когда запись переходит в `expiring` или `expired`
- прочитано / не прочитано
- клик ведёт на карточку записи
- дублируется в реальном времени по SSE всем открытым вкладкам
- дублируется Web Push на подписанные устройства (вкладка может быть закрыта)

### Журнал аудита

Фиксируются создание, изменение, удаление, продление записи и изменение категории:

- пользователь, время
- сущность и id
- значения до / после (краткий JSON)

Журнал доступен admin.

## Функциональные требования

Общие требования задания входят в этот список, а не живут отдельно.

### Must have (сдаём обязательно)

1. **CRUD записей** с валидацией на клиенте и сервере  
   обязательны title, kind, expires_at; cost ≥ 0; `started_at` не позже `expires_at`, если обе даты заданы; `attrs` проверяется по схеме типа.
2. **CRUD категорий** с иерархией до 3 уровней; **CRUD типов** (`item_kinds`) для admin.
3. **Список записей** с пагинацией, поиском и фильтрами:  
   текст (название, vendor, теги), kind, status, category, vendor, интервал `expires_at`, интервал стоимости, billing_period, тег.
4. **Карточка записи**: поля, статус, обратный отсчёт, история продлений, ссылка, подсказка аккаунта.
5. **Продление**: новая дата, опционально новая цена, запись в историю и в аудит.
6. **Дашборд**
   - карточки: всего активных, истекает за 7 дней, истекает за 30 дней, уже истекло, сумма ближайших продлений (месяц / год);
   - столбчатый график обязательств по месяцам на 6 месяцев вперёд (`monthly`/`yearly` — вхождения в окне, не одна `expires_at`; [Sprint 9](docs/sprint-9-plan.md));
   - круговая диаграмма расходов по типу или категории;
   - таблица «сгорит раньше всех» (топ-10).
7. **Календарь** на месяц: отметки дней с обязательствами (включая развёртку `monthly`/`yearly`), клик по дню открывает список. Навигация prev/next month.
8. **Импорт CSV** с маппингом колонок на поля записи (как в учебном трекере финансов).
9. **Экспорт CSV** текущего отфильтрованного списка.
10. **Реалтайм-уведомления** (SSE): смена статуса на `expiring` / `expired`, плюс колокольчик с непрочитанными.
11. **Роли admin / viewer**, JWT + refresh, два seed-аккаунта.
12. **Журнал аудита** для admin.
13. **Адаптивная вёрстка** desktop + mobile (список, дашборд, календарь, форма).
14. **PWA**: manifest, иконки, service worker, установка на домашний экран, офлайн-заглушка.
15. **Web Push**: разрешение в UI, доставка в ОС при закрытой вкладке.

### Should have (хотим в первой версии, можно урезать)

16. Массовая смена категории / статуса у выбранных записей (admin).
17. Быстрые пресеты порога уведомления: 7 / 14 / 30 дней на карточке.
18. Сортировка списка: по дате обязательства, стоимости, названию, обновлению.

### Out of scope (не делаем сейчас)

- email / Telegram;
- изоляция данных по организации (`org_id`), инвайты, роль viewer для чужого каталога — не делаем; прод после v1 — свои данные по пользователю, [Sprint 7](docs/sprint-7-plan.md);
- хранение паролей и секретов;
- автоматическое продление у регистратора / оплата;
- мультитенантность и приглашения в команду;
- вложения PDF/фото;
- iCal / Google Calendar;
- распознавание писем и чеков;
- полноценный биллинг и мультивалютный пересчёт в одну валюту (в демо просто разные `currency` у записей).

## Seed-данные

Реалистичный домашний + IT-набор:

- 2 пользователя (admin, viewer);
- ≥ 10 категорий, минимум 2 уровня;
- **50+ записей** за разные даты, из них:
  - ≥ 5 уже истекли,
  - ≥ 8 истекают в ближайшие 30 дней,
  - остальные распределены на 3–12 месяцев вперёд;
- типы: домены, подписки (GitHub, iCloud, Cursor), аренда (квартира / паркинг), страховка, полис ОСАГО, ТО, налоговый срок, лицензия ПО, договоры;
- ≥ 20 записей истории продлений (в т.ч. с изменением цены);
- ≥ 15 записей аудита;
- несколько непрочитанных уведомлений.

## Критерии «готово» для демо

Преподаватель после `docker compose up`:

1. входит как admin и как viewer;
2. видит дашборд с графиками и ненулевыми цифрами;
3. фильтрует список, открывает карточку, создаёт и правит запись;
4. продлевает запись и видит историю;
5. открывает календарь текущего месяца с отметками;
6. импортирует маленький CSV и экспортирует фильтр;
7. видит уведомление без перезагрузки (вторая вкладка или смена даты в seed/админке);
8. ставит PWA (Chrome) и при желании получает системный пуш;
9. открывает Swagger;
10. CI зелёный.

## Принятые решения (2026-08-21)

1. Фронтенд: React + TypeScript + Vite.
2. Общий список записей, роли admin / viewer.
3. Непустую категорию удалять нельзя.
4. Реалтайм: SSE во вкладке + Web Push в ОС.
5. Суммы на дашборде раздельно по валютам, без конвертации.
6. Регистрация открыта; в v1 новые пользователи — viewer, после Sprint 7 — admin со своими данными.
7. Массовые операции входят в v1.
8. Имя продукта Duekeep, репозиторий `expiry-calendar`.
9. Типы — справочник `item_kinds` + `attrs JSONB`; seed без ssl/warranty, есть `subscription` и `rent`.
10. JWT access (15 мин, память) + refresh (14 дней, ротация, cookie и/или body). Без cookie-сессии как единственного механизма.
11. Клиент — PWA. Auth закладываем под многопользовательское развитие; в v1 набор записей ещё общий.
