# API контракты Sprint 12

Источник: [`sprint-12-plan.md`](sprint-12-plan.md). База — сумма [`api-sprint-1.md`](api-sprint-1.md)…[`api-sprint-11.md`](api-sprint-11.md). Новый путь не добавляется. Меняется тело `GET /dashboard`. Календарь, меню и бейдж новых ручек не требуют.

## 1) Решения

- Четыре счётчика `counts` остаются в ответе. Интерфейс их не показывает.
- Деньги текущего месяца и число просроченных платежей считаются на сервере, тем же обходом вхождений, что график и статус.
- Валюты не конвертируются.
- `GET /calendar` не меняется: список месяца собирает клиент из `days`.

## 2) Dashboard

`GET /api/v1/dashboard`.

К прежнему телу добавляются:

```json
{
  "month_spend": [
    { "currency": "RUB", "total": 10000, "remaining": 4000, "overdue": 2000 }
  ],
  "overdue_count": 3
}
```

`month_spend` — массив, может быть пустым. Суммы в минимальных единицах валюты, как `cost_amount`.

- `total` — все вхождения с датой в текущем календарном месяце UTC;
- `remaining` — открытые из них с датой ≥ today;
- `overdue` — открытые из них с датой < today.

`overdue_count` — число открытых вхождений с датой < today по всему ряду записи (от `started_at`, иначе от якоря `expires_at`), без ограничения текущим месяцем.

`counts`, `upcoming_cost`, `expirations_by_month`, `cost_by_kind`, `soonest` не меняются.

## 3) Без изменений контракта

- `GET /calendar` — тот же ответ. Клиент без выбранного дня показывает все `days[].items`.
- Оплата вхождения — Sprint 10.
- Бейдж иконки — вызов `navigator.setAppBadge` в браузере, не поле API кроме `overdue_count`.
