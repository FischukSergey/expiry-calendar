# Known Limitations — Sprint 11

Черновик границ до реализации. После сдачи заменить на фактический долг, не на план.

## Сознательно оставляем

**Ряд не материализуется.** Будущие и прошлые monthly/yearly по-прежнему считаются в памяти. В `item_payments` только отмеченные дни.

**Два «оплачено».** Вхождение — платёж. `items.status = paid` — заморозка всей строки с формы.

**Справочник типов общий.** У записи нет своей копии `item_kinds`. Пишет только роль `administrator`. Смены роли в UI нет: назначение — env `ADMINISTRATOR_EMAIL` на сервере.

**Демо-каталога нет.** Старт не создаёт пользователей и записей. Роль `viewer` в схеме остаётся, новых viewer регистрация не создаёт. Шаблон категорий при регистрации остаётся. Уже залитый локальный volume эта миграция не чистит.

**Лимит login на один процесс.** Рестарт обнуляет счётчик. Несколько реплик не делят окно. Refresh не лимитируется.

**Integration не покрывает repository.** Тег `integration` проверяет commit reuse (и то, что задача больше не заглушка). Остальные тесты остаются на fake. Покрытие SQL не цель спринта.

**Фронт без e2e.** Vitest — отсчёт и порядок дат. Страницы, календарь и bulk вручную после регистрации.

**SSRF — проверка адреса, не прокси.** Редирект клиента Web Push на внутренний хост этим спринтом не разбирается отдельно, если проверка перед отправкой уже отсекла исходный URL. Повторная резолюция перед send закрывает подмену DNS между subscribe и отправкой.
