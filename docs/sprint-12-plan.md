# Sprint 12 — обзор месяца, список календаря, меню, бейдж

Источник: запрос после Sprint 11. Спринты 1–11 не переписываем. Модель оплаты вхождения остаётся. Код — только когда пользователь попросил реализовать спринт.

## 1) Цель

Обзор отвечает «сколько денег в этом месяце», а не «сколько записей в статусах». Календарь без выбранного дня показывает весь месяц. Левое меню на десктопе не уезжает вместе со страницей. Иконка установленного PWA показывает, сколько платежей уже просрочено.

К концу спринта:

- на «Обзоре» нет карточек «Активные», «7 дней», «30 дней», «Просрочены»;
- вместо них по каждой валюте: всего расходов текущего месяца, и внутри этой суммы — сколько ещё не оплачено и сколько из этого месяца уже просрочено;
- календарь без выбранного дня показывает все вхождения месяца; клик по дню оставляет только этот день;
- левая колонка меню на широком экране остаётся на месте, пока скроллится основная область;
- у установленного PWA на иконке бейдж с числом просроченных платежей; ноль бейдж снимает.

## 2) Что есть в коде

| Место | Факт |
|---|---|
| Обзор | Четыре карточки читают `counts.active`, `expiring_7`, `expiring_30`, `expired` (`DashboardPage.tsx`). Это число записей, не деньги. График, pie, run-rate «/ мес» и soonest живут отдельно и в этот запрос не входят. |
| Деньги месяца | `expirations_by_month` уже суммирует `cost_amount` вхождений по валютам за 6 месяцев вперёд, без конвертации. Оплаченный день в эту сумму тоже входит. Отдельной тройки «всего / осталось / просрочено» нет. |
| Календарь | `GET /calendar` отдаёт дни месяца с записями. Сайдбар рисует список только если день выбран (`selectedItems`). Пустой выбор — заголовок «День не выбран» и пустой список. Смена месяца выбор сбрасывает. |
| Меню | Десктоп: `aside` в обычном потоке, скролл общий со страницей. Мобильные вкладки уже `fixed` снизу. |
| PWA | Manifest и service worker есть. `navigator.setAppBadge` не вызывается. Бейдж у «Уведомлений» — это непрочитанные события, не просроченные платежи. |

## 3) Границы

### Входит

- карточки денег текущего месяца на обзоре вместо четырёх счётчиков;
- список всех вхождений месяца в календаре и сужение до дня;
- закрепление левой панели на `lg` и выше;
- бейдж иконки PWA по числу просроченных платежей;
- поле в `GET /dashboard` под эти цифры; OpenAPI и `docs/api-sprint-12.md`.

### Не входит

- экран редактирования справочника типов;
- смена ролей, seed, оплаты вхождения, soonest, графика и pie;
- бейдж в самой вёрстке меню (кружок непрочитанных остаётся как был);
- конвертация валют;
- подсчёт просрочки в service worker, пока приложение закрыто;
- e2e.

## 4) Техрешения

### Обзор

Текущий месяц — календарный месяц UTC, как остальные даты продукта.

Для каждой валюты три целых (`cost_amount`, копейки не вводим):

| Поле | Смысл |
|---|---|
| `total` | все вхождения, чья дата попадает в этот месяц: и оплаченные, и открытые |
| `remaining` | открытые вхождения этого месяца с датой ≥ today («осталось оплатить») |
| `overdue` | открытые вхождения этого месяца с датой < today («просрочено») |

Оплаченное в месяце входит только в `total`. Поэтому `remaining + overdue` не обязано равняться `total`.

Просроченный день прошлого месяца в эти три числа не входит: это не расход текущего месяца. Он по-прежнему виден в статусе записи, soonest и в бейдже. Заморозка `paid` / `cancelled` / `archived` вхождения не порождает.

Валюты не складываются. Нет сумм — блок не показываем. Одна валюта — одна карточка: крупно «всего», под ней две строки.

`counts` в JSON не удаляем: тесты и старый контракт на них опираются. Интерфейс их больше не рисует.

График «суммы оплаты по месяцам», pie, «/ мес» и таблица soonest остаются.

### Календарь

Нового запроса нет: список собирается из `days` ответа.

- день не выбран — все вхождения месяца, по дате, у строки видна дата; оплатить и снять оплату можно, дата берётся из строки;
- день выбран — только он, как сейчас;
- повторный клик по выбранному дню снимает выбор;
- смена месяца по-прежнему снимает выбор;
- в месяце нет вхождений — короткая пустая подсказка.

### Меню

На `lg` и выше `aside` — `sticky top-0 h-screen`. Страница скроллит основную колонку. Если пунктов больше высоты экрана, скролл внутри панели (`overflow-y-auto`). Нижние вкладки мобильного макета не трогаем: они уже закреплены.

### Бейдж PWA

Число — сколько открытых вхождений с датой < today есть у пользователя по всем месяцам ряда (не только текущий). Одно ежемесячное с тремя неоплаченными прошлыми днями даёт 3, не 1. Нижняя граница ряда та же, что у статуса: `started_at`, иначе якорь `expires_at`.

Число приходит в `GET /dashboard` полем `overdue_count`. Layout запрашивает тот же ключ кэша, что и обзор, и вызывает `navigator.setAppBadge`. Ноль — `clearAppBadge`. Нет API в браузере или отказ — молча, без ошибки в UI.

Пока вкладка закрыта, бейдж не пересчитывается: service worker не ходит в API. Последнее значение остаётся на иконке до следующего открытия.

## 5) Тесты

- сервис: месяц с оплаченным, будущим открытым и прошедшим открытым днём даёт ожидаемые `total` / `remaining` / `overdue`; вторая валюта не смешивается; день прошлого месяца не входит в тройку, но входит в `overdue_count`;
- UI глазами: обзор, календарь без дня и с днём, меню при длинной странице, бейдж в установленном Chrome.

## 6) Демо

1. Запись в текущем месяце: часть дней оплачена, один день месяца уже прошёл и не оплачен, один ещё впереди. Карточка валюты показывает все три числа. Четырёх старых счётчиков нет.
2. Неоплаченный день прошлого месяца не увеличивает «всего» текущего месяца и увеличивает бейдж.
3. Календарь открывается списком месяца. Клик по дню оставляет один день. Повторный клик возвращает месяц.
4. Длинная страница на широком экране: меню на месте, скроллится контент.
5. Установленный Chrome: на иконке число просроченных платежей; после оплаты последнего — бейджа нет.
