# Sprint 9 — оплачено, «мобильная связь», «не уведомлять», лента PWA

Источник: запрос после Sprint 8. Спринты 1–8 не переписываем. Сдача защиты — тег `v1.0.0`, этот спринт её не трогает.

## 1) Цель

Запись можно пометить **оплаченной**, в справочнике есть тип **«Мобильная связь»**, можно **не напоминать**, подписи нижней ленты PWA читаются на телефоне.

К концу спринта:

- статус `paid` («Оплачено») задаётся вручную, тикер его не затирает и **не шлёт уведомления** (предоплата до срока);
- в `item_kinds` десятый тип: slug `mobile`, имя «Мобильная связь» (`EnsureKinds` + локальный seed);
- у порога уведомления признак «не уведомлять»: нет push/SSE/строки в колокольчике, нет окна `expiring`;
- нижняя навигация PWA (`lg:hidden`) с более крупным шрифтом подписей.

## 2) Входные условия

- Sprint 7 закрыт: `owner_id`, register → admin, kinds общие на инсталляцию (сейчас 9 slug).
- Sprint 8 — CD; этот спринт не чинит деплой.
- Сейчас: статусы `active|expiring|expired|cancelled|archived`; `notify_before_days INT NOT NULL ≥ 0` (ноль = в день срока); лента `text-[11px]`; экрана создания kinds нет и **не добавляем**.

## 3) Границы

### Входит

- миграция: `status` допускает `paid`; `notify_before_days` может быть `NULL` («не уведомлять»);
- тикер, дашборд, календарь, список, карточка, форма, фильтр, bulk, CSV — `paid` и `null` notify;
- seed / `EnsureKinds`: тип `mobile` / «Мобильная связь» (стабильный UUID, ON CONFLICT по slug);
- форма записи: тип виден в селекте; чекбокс «Не уведомлять»; статус «Оплачено»;
- обзор и календарь: развёртка `monthly` / `yearly` по окну (сейчас только одна `expires_at`);
- нижняя лента PWA: крупнее подписи (ориентир `text-sm`), при необходимости чуть выше бар.

### Не входит

- отдельные строки в БД на каждое вхождение периода (только агрегаты в памяти);
- UI «добавить тип» / экран CRUD kinds (ручки Sprint 2 остаются, с формы не торчим);
- per-user `item_kinds`;
- визуальный конструктор `attr_schema`;
- оплата у оператора, эквайринг, чеки;
- почта / Telegram;
- `org_id`, шаринг;
- zero-downtime, смена CD;
- второй инстанс backend.

## 4) Backlog

### A. Статус `paid`

- CHECK и константы: плюс `paid`.
- Как `cancelled` / `archived`: только вручную (форма, PATCH, bulk). Тикер не переводит `paid` в `expiring`/`expired`.
- **Нет уведомлений при `paid`:** тикер не пишет notification и не шлёт SSE/push, даже если `notify_before_days` задан (срок ещё впереди — предоплата). Поле дней не обнуляем: после снятия `paid` / `renew` порог снова действует.
- Дашборд «сгорит» / суммы ближайших сроков и календарь открытых — без `paid`.
- Список: бейдж «Оплачено», фильтр `status=paid`.
- Продление (`renew`) с `paid` разрешено: новая дата, дальше статус считает тикер; колокольчик снова возможен.
- Seed: новые paid-строки не обязательны.

### B. Тип «Мобильная связь»

- `kindSeeds` + `EnsureKinds`: slug `mobile`, name «Мобильная связь», свой цвет, простой `attr_schema` (например номер телефона / оператор — по месту, без конструктора).
- `CheckCatalog` / `requiredKindSlugs`: 10 типов, не 9.
- Прод: `SEED=false`, тип появится при старте через `EnsureKinds` (как остальные 9).
- Категории не обязаны копировать тип: при желании подсказка категории, если в дереве есть подходящее имя; отдельная обязательная категория «Связь» — не блокер.
- UI создания kinds не делать.

### C. Не уведомлять

- `NULL` в `notify_before_days` = не уведомлять. `0` по-прежнему «в день `expires_at`».
- JSON: `notify_before_days: null`. Не слать отрицательные числа.
- Тикер: не пишет notification, не шлёт SSE/push; статус не становится `expiring` (остаётся `active` до дня срока, затем `expired`).
- Форма: чекбокс; при включении поле дней неактивно и в PATCH уходит `null`.
- CSV: пустая ячейка или `off` / `-` → `null`. Число как сейчас.

### D. Развёртка monthly/yearly в обзоре и календаре

Сейчас `expirations_by_month` и `GET /calendar` смотрят **только** `expires_at`. Netflix с сроком через год не рисуется в ближайших месяцах. `upcoming_cost` период уже учитывает (run-rate) — его формулу не ломать.

- Якорь — день `expires_at`. `monthly`: тот же день каждого месяца в окне; `yearly`: тот же месяц и день (и следующие годы, если окно захватывает). День 29–31 — clamp на последний день месяца.
- `one_time` — по-прежнему одна дата.
- Окно графика: текущий месяц UTC + 5, как сейчас. Календарь: запрошенный `year`/`month`.
- `cancelled` / `archived` не входят.
- `paid` (предоплата этого цикла): вхождение, совпадающее с текущим `expires_at`, не считать в график/календарь/«сгорит»; следующие циклы после этой даты — считать (следующий месяц / год).
- KPI `expiring_7` / `30` и `soonest`: ближайшее **ещё не оплаченное** вхождение, не сырой `expires_at`, если он уже `paid`.
- Новых колонок и таблицы расписания нет.

### E. Лента PWA

- Только нижний `nav` в [`Layout.tsx`](../frontend/src/components/Layout.tsx) (`lg:hidden`).
- Подписи крупнее, чем `11px`; бар не обрезает текст и safe-area.
- Десктопное меню слева не раздувать без нужды.

### F. Тесты и спека

- Тикер: `paid` не меняет статус и не создаёт notification; `notify_before_days=null` — нет notification и нет `expiring`.
- PATCH/create с `paid` и с `null` notify.
- Обзор: monthly даёт столбец не только в месяце `expires_at`; calendar в соседнем месяце видит ту же запись; `paid` прячет текущее вхождение, следующее остаётся.
- Seed/EnsureKinds содержит `mobile`.
- OpenAPI + [`api-sprint-9.md`](api-sprint-9.md).

## 5) Техрешения

- Одна goose-миграция после `011_owner_id.sql` (например `012_paid_notify.sql`): расширить CHECK `status`, снять `NOT NULL` с `notify_before_days`.
- Существующие строки: дни как были, не `NULL`.
- `NotifyBeforeDays` в Go — `*int` / sql null; в JSON `null` ≠ `0`.
- `paid` не вычисляется из денег и не ставится тикером. Для тикера «молчать» = `paid` **или** `notify_before_days IS NULL` (и как сейчас `cancelled`/`archived`).
- Новый kind — строка seed, не миграция SQL (как остальные slug).

## 6) DoD

- мобильная лента: подписи заметно крупнее, пять вкладок читаются;
- запись → «Оплачено» → бейдж, нет в KPI «сгорит», Tick не кладёт уведомление (даже при пороге 30 дней и близком сроке);
- в селекте типа есть «Мобильная связь»; на проде после рестарта backend — тоже (`EnsureKinds`);
- нет кнопки/экрана «добавить тип»;
- «не уведомлять» + Tick: колокольчик пустой, статус `active` до `expires_at`;
- monthly/yearly видны на графике 6 месяцев и в календаре не только в месяце одной `expires_at`;
- контракт [`api-sprint-9.md`](api-sprint-9.md), OpenAPI;
- [`known-limitations-sprint-9.md`](known-limitations-sprint-9.md);
- `task lint` и `task test`.
